# 고정 시간 순차 등장과 Lenis

스크롤은 Lenis 1.3.27 하나로 구동한다. GSAP/ScrollTrigger는 3.13.0이다. `new Lenis({smoothWheel:true, lerp:0.08})`, `scroll→ScrollTrigger.update`, GSAP ticker 하나의 `lenis.raf(time*1000)`, `lagSmoothing(0)`을 유지한다. 입력을 가공하거나 스크롤 엔진을 추가하지 않는다.

잇고를 참고한 구성 전체의 fade/fadeUp/popin/좌우 slide를 유지하되, 최신 사용자 요청(2026-11-09)에 따라 **모든 등장을 스크롤 진행률에서 분리**했다. 진입 후 멈추거나 빠르게 스크롤해도 동일한 duration으로 끝까지 재생한다. 스크롤 구간의 아래 경계는 항목의 top이 viewport 하단에 닿는 초기화선, 위 경계는 18%(최대 180px) 안쪽의 재생선이다. 아래로 재생선을 지나면 play하고, 위로 되돌려 초기화선 밖에 나가면 pause(0,false)한다. 따라서 작은 방향 반전에는 깜빡이지 않고, 항목이 화면 아래로 완전히 돌아간 뒤 재진입하면 같은 시간으로 반복한다.

| 구성 | 고정 시간 동작 |
|---|---|
| Hero | 기존 사진 y100→0, 설명 y-100→0, .8초 power1.out, .08초 간격 유지 |
| label / 원형 전략 카드 | popin scale .75→1(.575초 power1.out)→1.04(.175초)→1(.175초 sine.inOut). 전략 카드 3개는 제목이 먼저 읽히도록 .35초 뒤 시작해 좌→우 .21초 간격 |
| 제목·본문·질문·서체·Tool·로고·팔레트 | 완성된 구성 전체 opacity 0→1, .8초 sine.inOut. 같은 그룹 .15초 간격 |
| 문제 카드·기기 목업·화면·적용 사진·Flow | 전체 y100→0·opacity 0→1, .85초 power1.out, 그룹 간격 .15초 |
| 화면 annotation | 좌/우 폭의 ±25%→0·opacity 0→1, .8초 power1.out. 완성 후 유지하며 완전히 화면 아래로 돌아가면 재생 준비 |
| 리서치 막대 | 각 행의 진입 후 width와 카운트를 같은 progress로 .8초 power1.inOut에 완성. 설명은 .8초 fade, 행 간격 .15초 |
| 원그래프 | 동일한 SVG 중심·반지름·82% 부채꼴을 유지. 시계 방향 채움 1.1초 sine.inOut. .76초부터 caption .3초 fade와 숫자 .725초 카운트, 전체 약 1.485초에 완성 |
| 전략 카드 hover | 등장 scale과 별개로 translate y -9.6px, .3초 유지 |

각 항목의 최종 배치 top이 화면 하단에서 `Math.min(180, innerHeight*.18)`px 안으로 들어온 뒤 시작한다. 첫 항목 때문에 화면 아래 항목을 미리 재생하지 않는다. 원본 좌표로 시작점만 계산하고 런타임의 반복 bounds 측정은 추가하지 않는다. 앵커/키보드 탐색은 해당 섹션의 등장·차트 타임라인을 즉시 완성한다. 준비 실패/늦은 첫 화면의 안전한 읽기 경로는 유지한다.

## 중간 속도·재진입 검수 (2026-11-09)

최신 요청으로 fade/설명 .8초, fadeUp .85초, popin .925초(.575+.175+.175), 막대 .8초로 두 버전의 중간 시간을 적용했다. 같은 그룹 .15초, 전략 카드는 .21초 간격이며 제목을 위한 .35초 선행 간격은 유지했다. 원그래프는 기존 속도가 scrub에 의존해 고정 시간 비교가 불가능하므로, 채움 1.1초와 후속 숫자 .725초(전체 1.485초)로 직전보다 짧게 조정했다.

1920×1080에서 파이의 완성 82% → 진입선 조금 위에서도 82% 유지 → 화면 밖으로 되돌렸을 때 채움/숫자/opacity 모두 0 → 재진입 시 중간 채움 74.44% → 82% 완성을 확인했다. 카드도 작은 역방향에서는 opacity 1을 유지했고, 완전히 화면 밖에서는 모두 0, 재진입 진행 중 .925/.590/0으로 순서를 확인했다. 두 번째 재생의 카드 시작 간격은 201/217ms였다. 1280×900에서 CLASS 설명도 완성→화면 밖 초기화→재생을 확인했다. 두 검사 폭에서 관련 console 오류·경고가 없었다. 실제 큰 휠 입력으로 위까지 되돌린 뒤 전체 페이지를 다시 통과했을 때 102개 구성이 모두 entered였고, 지나간 영역에 opacity 0 항목이 없었다. 임시 QA 제어·샘플러는 배포 소스에 포함하지 않는다.

## 직전 느린 버전의 고정 시간 등장 검수 (2026-11-09)

인앱 브라우저 1920×1080 및 최소 PC 폭 1280×900에서 확인했다. 원그래프는 0% 초기 상태 → 스크롤 정지 중 23.36%/중간 채움 → 82% 최종 상태를 확인했다. 같은 scrollY에서 채움이 약 1.3초, 후속 숫자가 전체 약 1.75초에 완성됐다. 위로 되돌려도 82%와 caption이 유지됐다.

전략 제목은 레이블→본문 순서로 각각 자기 진입선 이후 재생됐다. 원형 카드 초기 opacity는 모두 0, 진행 중 .856/.392/0으로 좌→우 차이가 보였고 최종 opacity/scale은 모두 1이었다. 실측 카드 시작 간격은 약 300ms였으며 큰 휠 입력에서도 299/302ms로 유지됐다. 전체 popin은 1.15초이고, opacity가 거의 완성되는 시점은 약 .66~.71초였다. 카페 사진은 정지 상태에서 약 1.02초, CLASS 설명은 약 .91초에 opacity .995 이상이 됐고 이후 되돌려도 entered 상태를 유지했다.

실제 큰 휠 입력으로 전체 페이지를 통과한 뒤 역스크롤했을 때 102개 구성 모두 entered였고 opacity 0으로 남은 항목이 없었다. 두 검사 폭 모두 앱 console error/warn가 없었다. 임시 진입 버튼/DOM 샘플러는 로컬 QA 서버에서만 주입했고 배포 소스에는 포함하지 않는다. 큰 휠 입력에서 제목이 카드보다 먼저 읽히도록 .35초 선행 간격을 추가한 뒤 다시 검사했으며, 본문 제목의 실제 opacity 시작 후 약 145ms 뒤 첫 카드가 시작했고 이후 카드 간격은 301/298ms였다. 최종 정적 배치·원본 자산·Lenis 감도는 변경하지 않았다. 특정 Windows 인앱 브라우저의 검사이며 모든 기기의 무지연을 뜻하지 않는다.

## 목업 렌더링

전체 섹션 크기로 잡던 wrapper는 앞선 수정에서 실제 경계로 제한했다. 이번에는 30개 이미지 컨테이너의 RGB 원본과 alpha/luminance 마스크를 미리 합쳐 24개 무손실 투명 WebP로 연결했다. 필수 투명도·크롭과 원본 배치는 유지한다. 단색/둥근 SVG 배경 11곳은 같은 색·크기의 CSS로 바꿨다. native 문서 스크롤에서는 content-visibility:auto의 큰 섹션 활성화를 사용하지 않으며 브라우저의 기본 culling과 native lazy image를 사용한다.

## 첫 방문과 새로고침

Lenis는 폰트·히어로 decode를 기다리기 전에 시작한다. 이미지 디코드는 화면 높이 4배(최대 4000px) 근처에서 idle에 한 장씩 처리하며 WebP·PNG·JPEG만 수동 큐에 포함한다. 500px 안의 구성만 합성 레이어를 준비하고 벗어나면 해제한다. wrapper는 paint 경계를 제한한다. 잘난체는 첫 모션 설정 전에 준비해 중간 스크롤 중 글꼴 교체를 피한다. 고정 tween은 resize refresh 때 invalidate하지 않는다. 모든 이미지에 async decode를 명시한다. 배치·이미지 치수와 기존 렌더링 최적화는 유지하고 등장 시간만 위 표의 최신 값으로 조정한다.

1920×1080 인앱 브라우저에서 로컬 자산 URL을 새로 만들어 첫 방문을 검사하고 같은 URL을 새로고침했다. 각 휠 입력 뒤 1.6초 RAF 표본을 수집하고 화면/AX 수집은 표본 종료 후 수행했다. 2페이지 입력 9회로 전체를 통과했을 때 첫 방문 최대17~19ms, 새로고침 최대17~21ms, 50ms 초과0회였다. 4페이지씩 한 번에 넘기는 별도 입력에서는 83~233ms 단발 프레임도 관측해 모든 입력·기기의 무지연으로 일반화하지 않는다. 외부 CDN의 완전히 비어 있는 캐시는 이 로컬 자산 검사와 구분한다.

## 이전 확인 근거

1280×720 PC 브라우저에서 GUI 시작→20회 동일 .35페이지 휠 입력으로 메인 화면까지 비교했다. 이전 버전 d46d526의 50ms 초과 프레임 55회/평균26.09ms/최대897.3ms, 수정 후 1회/평균16.89ms/최대100ms를 기록했다. 실행 환경·캐시·진입 상태에 따라 수치는 달라지며 모든 기기의 무지연을 보장하지 않는다. 원본과 미리 합친 자산의 전체 비교는 1280×15,421px 정적 캡처로 수행했다. 레이아웃·텍스트는 유지하며 이미지 리샘플링·투명도·둥근 모서리에서 소폭 픽셀 차이가 있다. 원본 1920×23,132의 ?capture=1도 유지한다.

## 2026-11-08 최종 스크롤 정책

사용자 최종 요청으로 큰 휠 입력의 native 전환과 방향 반전 보정을 제거했다. 큰 입력·작은 입력 모두 smoothWheel:true, lerp:.08의 기본 Lenis를 사용하며 virtualScroll 콜백·휠 거리 변환·반전 시 scrollTo 호출은 없다. 단일 GSAP ticker와 기존 등장 시작 위치·차트·역스크롤 연출은 유지한다.

메인 화면 목업의 정적인 CSS polygon 잘림은 같은 1112×3722 RGBA에 반영한 lossless WebP로 유지한다(1,433,252 → 1,426,474 bytes). 125% 캡처의 해당 섹션 전후 픽셀 차이는 0이었다. 앞선 native burst 비교 수치는 최종 입력 방식의 검증 결과로 사용하지 않는다.
