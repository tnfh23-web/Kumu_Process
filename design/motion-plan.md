# 모션 적용과 근거

근거: https://r00neyj.github.io/Eatgo_Process/ 및 로컬 skills-hooks의 section-entry-sequence.md, counter-chart-reveal.md, scroll-smoother.md. Eatgo에서 레이블/제목·본문·자료의 시차, 차트 수치/막대 완성, GUI 화면/설명의 등장, 로고 pop과 목업 진입을 확인했다. 색·데이터·화면·문구는 복제하지 않는다.

| 구간 | 적용 | 실제 확인 방법 |
|---|---|---|
| Hero | 미디어 진입 → 메타 정보와 워드마크 조각 → 프로젝트 설명 | 새 진입에서 준비/진행/완료 캡처와 opacity 차이 |
| Overview | label → 제목 → 설명 | 진입 후 스크롤을 멈춰도 완성 |
| Desk Research | 제목/설명 → 조사 질문 → 파이 pop, 막대 scaleX → 숫자 완성 | 82, 37, 28, 21, 14의 최종값과 원본 주석 |
| Problem / Goal | 제목 → 3개 카드 시차 → 연결 삼각형 → 목표 문구 | 카드별 시차와 목표의 완성 위치 |
| Strategy | 제목 → 3개 원 개별 등장, 번호 hover | 원 3개가 하나의 큰 사각 레이어로 취급되지 않는지 |
| Naming / Logo | 제목·본문 순서, 벡터 조각의 짧은 pop/마스크 등장 | 작은 눈·라인·로고의 완료 상태 |
| Design System | 서체 샘플, 팔레트와 코드 순차 등장 | 글자와 스와치 위치, 색 코드 hover 복원 |
| GUI | label/제목 → 기기 목업 창 → grid | 입력 정지 후 이미지·설명 모두 완성 |
| Brand Application | 사진과 목업의 큰 창 열기, 개별 자료 진입 | 투명 영역이 검게 남지 않는지, 비율·마스크 |
| User Flow | 제목 → 진행선/노드 → 6개 단계 순서 | 요소별 진입과 01~06의 최종 가시 상태 |
| Main / Sub | 제목 → 화면 → 폰/설명 좌우 진입 | 원본 좌표, 이미지와 텍스트가 독립 동작 |
| Closing | 목업 → 워드마크/크레딧 → 마무리 | 페이지 끝 도달, 원래 배경색과 이미지 투명도 |

ScrollSmoother는 다른 ScrollTrigger보다 먼저 1개만 생성한다. 설정은 smooth 1.05, smoothTouch .1이며 CSS smooth/다른 보간 RAF와 중복하지 않는다. 등장 자체는 독립된 0.8~1.1초 타임라인, 그룹 내부 지연은 0.14초 단위로 겹친다. 긴 목록은 가까운 행끼리 묶는다. 차트는 최대 1.95초 정도에 최종값으로 정착한다.

원본 레이아웃의 회전·반전은 내부 wrapper가, 등장 이동은 바깥 노드가 담당한다. 사용자 OS 모션 설정만으로 연출을 끄지 않는다. 초점/앵커 진입은 관련 그룹을 즉시 완성하고, 초기화 실패는 숨김과 고정을 해제한다. 자료는 첫 완성 이후 유지하며 역스크롤 경계에서 반복적으로 깜박이지 않는다. QA용 정적 모드는 실제 효과의 증거로 사용하지 않는다.
